C# básico: plataforma, tipos, operadores, controle de fluxo, métodos, exceções e arquivos

Este capítulo constrói a base da linguagem C# exigida no edital de Analista de Sistemas. O objetivo não é só saber "o que é" cada recurso, mas conseguir prever a saída de um trecho de código e identificar o que compila e o que não compila, que é a forma mais comum de cobrança da FGV. No final, há um panorama de outras linguagens e tecnologias web (JavaScript, Java, HTML5, CSS3 e WSDL) que costumam ser cobradas no mesmo bloco de "linguagens de programação".

1. A plataforma .NET e o caminho do código C#

O C# é uma linguagem orientada a objetos, fortemente tipada, criada pela Microsoft no início dos anos 2000 para a plataforma .NET. Hoje o .NET é multiplataforma (Windows, Linux e macOS) e de código aberto. Entender como um programa C# chega a ser executado ajuda a responder questões que perguntam se a linguagem é "compilada" ou "interpretada" e o que acontece em cada etapa.

  1. Compilação para linguagem intermediária. O compilador do C# (Roslyn, acionado pelo dotnet build ou pelo Visual Studio) não gera código de máquina. Ele traduz o código-fonte para CIL (Common Intermediate Language, também chamada de MSIL ou IL), que fica dentro de um assembly (arquivo .dll ou .exe) junto com os metadados dos tipos.
  2. Execução pelo CLR. O Common Language Runtime é a máquina virtual do .NET. Na hora de executar, o compilador JIT (just-in-time) converte o IL em código de máquina nativo do processador, método por método, conforme eles são chamados.
  3. Serviços do runtime. O CLR também cuida do gerenciamento automático de memória (coletor de lixo, o garbage collector), da verificação de tipos, do tratamento de exceções e da segurança. Por isso se diz que o código C# é código gerenciado.

Como várias linguagens (C#, F#, VB.NET) compilam para o mesmo IL, elas conseguem usar as bibliotecas umas das outras. Os tipos básicos comuns a todas formam o CTS (Common Type System): o int do C# é, na verdade, o tipo System.Int32 do .NET.

Na provaC# e Java são linguagens híbridas: compiladas para um código intermediário (IL no .NET, bytecode na JVM) e depois executadas por uma máquina virtual com compilação JIT. Uma alternativa que diga que o C# é "interpretado linha a linha", como um script, está errada.

2. Estrutura de um programa

Todo programa de console tradicional tem a mesma "casca". Saber reconhecê-la permite ir direto ao que importa, que é o corpo do método Main:

using System;                  // importa o namespace System (Console, Math, Exception...)

namespace Financeiro           // namespace: agrupa classes e evita conflito de nomes
{
    class Program              // toda instrução executável fica dentro de um tipo
    {
        static void Main(string[] args)    // ponto de entrada do programa
        {
            Console.WriteLine("Olá, INB");  // escreve e quebra a linha
        }
    }
}
  • using no topo do arquivo apenas permite escrever Console em vez de System.Console. Não "importa código" para dentro do programa.
  • Main é o ponto de entrada. Ele é static (pertence à classe, não a um objeto) e pode retornar void, int, Task ou Task<int> (os dois últimos com async, desde o C# 7.1) e receber ou não string[] args (os argumentos da linha de comando).
  • Desde o C# 9 existem as instruções de nível superior (top-level statements): um arquivo pode conter só Console.WriteLine("Olá"); e o compilador gera a classe e o Main automaticamente. A forma "completa" acima continua válida e é a que aparece na maioria das questões.
  • O C# diferencia maiúsculas de minúsculas: Main e main são nomes diferentes, e console.writeline não compila.
  • Toda instrução termina com ; e os blocos são delimitados por chaves. Comentários: // linha, /* bloco */ e /// documentação XML.

3. Sistema de tipos

O C# é fortemente e estaticamente tipado: o tipo de toda variável é conhecido em tempo de compilação, e o compilador recusa operações incompatíveis (por exemplo, atribuir uma string a um int). Todos os tipos derivam, direta ou indiretamente, de System.Object (object), e se dividem em dois grandes grupos.

Arrays são tipos de referência mesmo quando os elementos são int. Esse detalhe aparece em questões de "qual o valor final".

Boxing e unboxing. Quando um tipo de valor é tratado como object, o runtime cria uma cópia dele no heap (boxing): object o = 42;. Recuperar o valor exige um cast explícito para o tipo exato (unboxing): int n = (int)o;. Fazer (long)o nesse caso gera InvalidCastException, porque o valor encaixotado é um int.

Pontos que costumam ser cobrados:

  • Um literal inteiro sem sufixo é int; um literal com ponto decimal sem sufixo é double. Por isso float f = 1.5; não compila (seria perda de precisão de double para float); o correto é 1.5f. O mesmo vale para decimal d = 1.5; (precisa de m).
  • bool não se converte de/para números. Diferente de C, if (1) não compila.
  • char usa aspas simples e é numérico por baixo: 'A' + 1 resulta no int 66. Já string usa aspas duplas.
  • float e double são binários e não representam exatamente frações decimais: 0.1 + 0.2 == 0.3 é false com double. Para valores monetários, a resposta esperada é decimal.

4. Variáveis, constantes e conversões

int idade = 30;                  // declaração com inicialização
int a, b = 5;                    // a é declarada sem valor; b recebe 5
var nome = "Ana";                // tipagem implícita: o compilador deduz string
const double Taxa = 0.15;        // constante de compilação
readonly int limite;             // (em campos de classe) atribuído só na declaração ou no construtor
  • Atribuição definida. Uma variável local precisa receber valor antes de ser lida. int a; Console.WriteLine(a); é erro de compilação ("uso de variável local não atribuída"), não erro de execução. Campos de classe, por outro lado, recebem o valor padrão automaticamente.
  • var não torna a variável dinâmica: o tipo é fixado na compilação e não muda depois. Exige inicialização na mesma instrução (var x; e var y = null; não compilam) e só vale para variáveis locais. Já dynamic adia a verificação de tipo para a execução.
  • const exige um valor conhecido em tempo de compilação (literais e expressões com literais) e é implicitamente estático. readonly é para campos que só podem ser atribuídos na declaração ou no construtor, com valor calculado em tempo de execução.
  • Escopo. Uma variável vale do ponto em que é declarada até o fim do bloco { } em que foi declarada. Não é permitido declarar, num bloco interno, outra variável com o mesmo nome de uma variável local ainda visível.

Conversões

Tipo de conversãoQuando ocorreExemplo

  • int.Parse("abc") lança FormatException. int.TryParse("abc", out n) não lança nada: devolve false e deixa n = 0.
  • Convert.ToInt32(2.5) arredonda para o par mais próximo (arredondamento bancário): 2.5 vira 2 e 3.5 vira 4. Já o cast (int)2.5 trunca para 2. Convert.ToInt32(null) retorna 0, enquanto int.Parse(null) lança exceção.
  • Overflow. Por padrão, a aritmética inteira é unchecked: int.MaxValue + 1 "dá a volta" e vira int.MinValue, sem erro. Dentro de um bloco checked { }, o mesmo cálculo lança OverflowException. Se a expressão for toda de constantes, o compilador detecta e recusa.

5. Tipos anuláveis e os operadores de null

Tipos de valor não aceitam null. Para representar "sem valor" (um campo opcional vindo do banco de dados, por exemplo), usa-se o tipo de valor anulável T?, que é uma abreviação de Nullable<T>. Ele expõe HasValue (bool), Value (lança InvalidOperationException se estiver null) e GetValueOrDefault().

int? idade = null;
if (idade.HasValue) Console.WriteLine(idade.Value);
int certa = idade.GetValueOrDefault();   // 0
int x = idade;          // ❌ não compila: int? não converte implicitamente para int
int y = (int)idade;     // compila, mas lança InvalidOperationException em execução (está null)

Coalescência nula: ?? e ??=

a ?? b devolve a se ele não for null; caso contrário, devolve b. O lado direito só é avaliado quando necessário. É uma escolha, não uma conta. Encadeado, a ?? b ?? c devolve o primeiro valor não nulo da esquerda para a direita. x ??= y atribui y a x somente se x for null.

int? a = null;   int? b = 30;   double? c = 2.5;
Console.WriteLine(a ?? b);       // 30
Console.WriteLine(b ?? a);       // 30   (b não é null, então fica com b)
Console.WriteLine(b ?? c);       // 30   (o resultado é double?, mas 30.0 é impresso como 30)
Console.WriteLine(c ?? b);       // 2.5
Console.WriteLine(a ?? -1);      // -1
int? d = null;
Console.WriteLine($"[{a ?? d}]"); // []   (null ?? null = null, impresso como texto vazio)

Outro operador da família é o condicional nulo ?. (e ?[]): cliente?.Nome devolve null em vez de lançar NullReferenceException quando cliente é null. Combinado com ??: cliente?.Nome ?? "sem nome".

Operadores com anuláveis ("lifted operators")

Os operadores aritméticos aplicados a anuláveis devolvem null se qualquer operando for null: int? n = null; n + 5 é null. As comparações seguem uma regra própria, que precisa ser decorada:

ComparaçãoUm lado nullOs dois lados null
< > <= >=falsefalse
==falsetrue
!=truefalse

A consequência contraintuitiva: se p é null, p < 10 e p >= 10 são ambas falsas. Não vale o raciocínio "se não é menor, então é maior ou igual".

Exemplo resolvido 
int? p = null;  int q = 10;  int? r = null;
Console.WriteLine(p > q);    // False
Console.WriteLine(p <= q);   // False
Console.WriteLine(q != p);   // True
Console.WriteLine(q == p);   // False
Console.WriteLine(r == p);   // True
Lembre também que Console.WriteLine imprime valores bool como True e False, com inicial maiúscula.

6. Operadores e precedência

Aritméticos

+ - * / %. Dois pontos exigem atenção:

  • Divisão inteira. Se os dois operandos são inteiros, o resultado é inteiro e a parte fracionária é descartada: 7 / 2 = 3, -7 / 2 = -3 (trunca em direção a zero). Basta um operando ser real para a divisão ser real: 7 / 2.0 = 3.5. Dividir um inteiro por zero lança DivideByZeroException; dividir um double por zero dá Infinity (ou NaN em 0.0 / 0).
  • Resto (%). a % b é o que sobra da divisão inteira: 32 % 3 = 2, porque 3 × 10 = 30 e sobram 2. Quando o dividendo é menor que o divisor, o resto é o próprio dividendo: 4 % 9 = 4. O sinal do resultado segue o do dividendo: -7 % 3 = -1 e 7 % -3 = 1. Usos clássicos: n % 2 == 0 (par), n % 10 (último dígito).

Incremento e decremento

Os operadores ++ e -- somam ou subtraem 1 de uma variável. A diferença entre as formas está no valor da expressão:

  • Pré-fixado (++x): incrementa primeiro; a expressão vale o valor novo.
  • Pós-fixado (x++): a expressão vale o valor antigo; o incremento acontece logo depois.
int a = 5;
int b = ++a;        // a = 6, b = 6
int c = a++;        // c = 6, a = 7
int d = ++a + 1;    // a = 8, d = 9
int e = a++ + a;    // 8 + 9 = 17, a = 9  (avaliação da esquerda para a direita)
a = a++;            // a continua 9: a expressão vale 9 e a atribuição grava 9 por cima do incremento
Armadilha clássicaEm v = v++ + 2;, o incremento "se perde": a expressão usa o valor antigo de v, e a atribuição final sobrescreve o incremento. O C#, diferente de C e C++, define rigorosamente a ordem (operandos avaliados da esquerda para a direita), então o resultado é sempre previsível.

Curto-circuito. && e || só avaliam o operando da direita se for necessário: em falso && X e em verdadeiro || X, X nunca é executado. Isso é usado para proteger acessos, como em if (s != null && s.Length > 0). Já & e | com bool avaliam sempre os dois lados; se o lado direito tiver efeito colateral (um i++, uma chamada de método), o resultado muda.

Curto-circuito na prática 
int i = 0;
bool r1 = (i > 5) && (++i > 0);   // i continua 0 (lado direito não avaliado)
bool r2 = (i > 5) &  (++i > 0);   // i vira 1  (os dois lados avaliados)
Console.WriteLine($"{r1} {r2} {i}");   // False False 1

Atribuição, ternário e outros

Atribuições compostas: += -= *= /= %= &= |= ^= <<= >>= ??=. O operador condicional (ternário) cond ? a : b devolve a se a condição for verdadeira e b se for falsa: string s = nota >= 7 ? "aprovado" : "reprovado";. Outros operadores úteis: is (testa o tipo: if (obj is string txt)), as (converte ou devolve null), typeof(T), sizeof(int) (= 4), nameof(x).

Operadores do mesmo nível são avaliados da esquerda para a direita, exceto atribuição, ?? e ternário, que associam da direita para a esquerda. Exemplos: 2 + 3 * 4 = 14; 10 - 4 - 3 = 3; 1 + 8 >> 1 = 4 (a soma vem antes do deslocamento: 9 >> 1); true || false && false é true (o && é avaliado primeiro).

Rastreio completo com array 
int[] v = { 12, 20, 17 };
v[0] = v[0] >> 1;      // 12 ÷ 2 = 6
v[1] = v[1]++ + 2;     // a expressão usa 20; 20 + 2 = 22 é gravado por cima do incremento
v[2] = v[2] % 5;       // 17 = 5 × 3 + 2 → 2
foreach (int n in v) Console.WriteLine(n);   // 6, 22, 2
Com ++v[1] + 2, o resultado seria 21 + 2 = 23.

7. Strings e saída no console

A string é um tipo de referência imutável: métodos como ToUpper(), Replace() e Trim() não alteram a string original, e sim devolvem uma nova. Em laços que concatenam muito texto, usa-se StringBuilder (namespace System.Text), que é mutável. Apesar de ser tipo de referência, o operador == entre strings compara o conteúdo, não o endereço.

string s = "Concurso";
s.ToUpper();                 // não muda s
s = s.ToUpper();             // agora s = "CONCURSO"
Console.WriteLine(s.Length);         // 8 (propriedade, sem parênteses)
Console.WriteLine(s[0]);             // C (índice começa em 0)
Console.WriteLine(s.Substring(2, 3));// NCU (a partir do índice 2, 3 caracteres)

Concatenação com números segue a precedência e a ordem da esquerda para a direita:

Console.WriteLine("R" + 1 + 2);     // R12  (string + 1 = "R1"; "R1" + 2 = "R12")
Console.WriteLine(1 + 2 + "R");     // 3R   (1 + 2 = 3 antes de encontrar a string)
Console.WriteLine("R" + (1 + 2));   // R3

Formatação. Formato composto: Console.WriteLine("{0} tem {1} anos", nome, idade);, em que os números entre chaves são as posições dos argumentos (um mesmo índice pode se repetir). Interpolação: $"{nome} tem {idade} anos". Especificadores: {0:F2} (2 casas decimais), {0:N} (separador de milhar), {0:C} (moeda), {0:D5} (inteiro com 5 dígitos). Write não quebra a linha; WriteLine quebra. Para leitura, Console.ReadLine() devolve uma string, que precisa ser convertida para número.

8. Estruturas de decisão

if / else

if (nota >= 7)
    Console.WriteLine("Aprovado");
else if (nota >= 5)
    Console.WriteLine("Recuperação");
else
    Console.WriteLine("Reprovado");

A condição precisa ser uma expressão bool. Por isso if (x = 5) não compila em C# (em C compilaria e seria um erro lógico). Sem chaves, o if controla apenas a próxima instrução; um else se liga ao if mais próximo que ainda não tenha else.

switch

switch (opcao)
{
    case 1:
    case 7:                         // rótulos vazios podem ser empilhados
        Console.WriteLine("Fim de semana");
        break;
    case 2:
        Console.WriteLine("Segunda");
        goto case 3;                // transferência explícita é permitida
    case 3:
        Console.WriteLine("Útil");
        break;
    default:                        // opcional; pode aparecer em qualquer posição
        Console.WriteLine("Inválido");
        break;
}
  • O C# não permite fall-through implícito: toda seção com instruções precisa terminar com break, return, throw, continue (dentro de um laço) ou goto case. Esquecer o break é erro de compilação, não comportamento silencioso como em C e Java.
  • Aceita expressões de tipos integrais, char, string, enum e, desde o C# 7, padrões: case int n when n > 0:.
  • Não pode haver dois case com o mesmo valor constante.

Expressão switch (C# 8; os padrões or, and e >= usados no exemplo são do C# 9), que produz um valor:

string nome = dia switch
{
    1 or 7 => "fim de semana",
    >= 2 and <= 6 => "dia útil",
    _ => "inválido"            // _ é o descarte, equivale ao default
};

9. Estruturas de repetição

LaçoTesteExecuta no mínimoUso típico
for (init; cond; passo)antes de cada volta0 veznúmero de repetições conhecido
while (cond)antes de cada volta0 vezrepetir enquanto uma condição valer
do { } while (cond);depois de cada volta1 vezmenus, validação de entrada
foreach (var x in colecao)enquanto houver elementos0 vezpercorrer arrays e coleções

Como o for executa: (1) a inicialização roda uma vez; (2) a condição é testada; se falsa, o laço termina; (3) o corpo roda; (4) o passo roda; volta ao item 2. As três partes são opcionais: for (;;) é um laço infinito válido, equivalente a while (true), que só termina com break, return ou uma exceção. A inicialização e o passo aceitam várias expressões separadas por vírgula: for (int i = 0, j = 10; i < j; i++, j--).

Quantas voltas? for (int i = a; i < b; i++) executa b − a vezes; com <=, b − a + 1 vezes. Ao terminar, a variável vale o primeiro valor que tornou a condição falsa (com i < 5, i termina valendo 5).

foreach: a variável de iteração é somente leitura (x = 0; dentro do laço não compila), e adicionar ou remover itens de uma List enquanto ela é percorrida lança InvalidOperationException.

break e continue

  • break encerra o laço (ou o switch) mais interno imediatamente.
  • continue pula o restante da volta atual e vai para o próximo teste (no for, executa o passo antes).
Contando chamadas 
for (int i = 1; i <= 6; i++) {
    if (i % 3 == 0) break;
    A(i);                 // i = 1 e 2 → A é chamada 2 vezes; em i = 3 o laço acaba
}
for (int i = 1; i <= 6; i++) {
    if (i % 3 == 0) continue;
    B(i);                 // pula 3 e 6 → B é chamada 4 vezes (1, 2, 4, 5)
}
O valor inicial é decisivo. Se o laço começasse em i = 0 com o teste i % 3 == 0 e break, ele terminaria na primeira volta (0 % 3 = 0), e A nunca seria chamada. Com continue, o 0 também seria pulado.

Escopo da variável do laço

A variável declarada no cabeçalho do for (ou do foreach) existe somente dentro do laço. Referenciá-la depois é erro de compilação ("o nome 'i' não existe no contexto atual"), então o programa nem chega a ser executado.

for (int i = 0; i < 5; i++) { }
Console.WriteLine(i);      // ❌ erro de compilação

int j;
for (j = 0; j < 5; j++) { }
Console.WriteLine(j);      // ✅ 5, porque j foi declarada fora do laço

for (int k = 0; k < 3; k++) { }
for (int k = 0; k < 3; k++) { }   // ✅ válido: cada k vive no seu próprio laço

10. Arrays

Um array é uma coleção de tamanho fixo de elementos do mesmo tipo, com índices começando em 0. É um tipo de referência, e seus elementos recebem automaticamente o valor padrão do tipo.

int[] a = new int[3];               // {0, 0, 0}
int[] b = { 4, 16, 8 };             // inicialização direta
string[] c = new string[2];         // {null, null}
Console.WriteLine(b.Length);        // 3 (propriedade)
Console.WriteLine(b[3]);            // ❌ IndexOutOfRangeException (em execução)

int[,] m = new int[2, 3];           // matriz retangular 2 × 3
m[1, 2] = 7;
Console.WriteLine(m.GetLength(0));  // 2 linhas;  m.GetLength(1) = 3 colunas;  m.Length = 6

int[][] serr = new int[2][];        // jagged array: array de arrays
serr[0] = new int[] { 1, 2 };
serr[1] = new int[] { 3, 4, 5 };    // as linhas podem ter tamanhos diferentes

A classe System.Array oferece métodos estáticos como Array.Sort, Array.Reverse, Array.IndexOf e Array.Resize. Quando o tamanho precisa variar, o normal é usar List<T> (com Add, Remove e Count).

11. Métodos e passagem de parâmetros

Um método é um bloco de código com nome, parâmetros e tipo de retorno. A assinatura é formada pelo nome e pela lista de parâmetros (quantidade, tipos, ordem e modificadores). O tipo de retorno não faz parte da assinatura para fins de sobrecarga.

static int Soma(int a, int b) { return a + b; }
static int Dobro(int x) => x * 2;                  // corpo de expressão
static double Soma(double a, double b) => a + b;  // sobrecarga: tipos diferentes
static void Saudar(string nome, string pre = "Olá") => Console.WriteLine($"{pre}, {nome}");
static int Total(params int[] v) { int s = 0; foreach (int n in v) s += n; return s; }

Saudar("Ana");                    // Olá, Ana
Saudar(pre: "Oi", nome: "Bia");   // argumentos nomeados, em qualquer ordem
Total(1, 2, 3);                   // 6 (params aceita quantidade variável)
  • static × instância. Um método static pertence à classe e é chamado pelo nome da classe (Math.Max(3, 5)); não acessa membros de instância diretamente. Um método de instância precisa de um objeto (conta.Depositar(100)).
  • Sobrecarga (overload): vários métodos com o mesmo nome e listas de parâmetros diferentes. Dois métodos que diferem apenas no tipo de retorno não compilam.
  • Parâmetros opcionais têm valor padrão constante e precisam vir depois dos obrigatórios. params precisa ser o último parâmetro e só pode haver um.
  • Recursão: um método pode chamar a si mesmo; precisa de um caso base, senão estoura a pilha (StackOverflowException).

Passagem por valor e por referência

Por padrão, todo argumento é passado por valor: o método recebe uma cópia. Para tipos de valor, isso significa que alterar o parâmetro não muda a variável de quem chamou. Para tipos de referência, a cópia é da referência: o método pode alterar o conteúdo do objeto (os elementos de um array, por exemplo), mas não consegue fazer a variável de quem chamou apontar para outro objeto.

ModificadorInicializar antes da chamada?O método deve atribuir?Uso
(nenhum)simnãoentrada comum (cópia)
refsimnãoentrada e saída: o método pode alterar a variável original
outnãosim, antes de retornarretornar valores extras (int.TryParse(s, out n))
insimnão pode alterarpassar por referência só para leitura (evita cópia de structs grandes)

O modificador aparece também na chamada: Dobrar(ref n);, int.TryParse(s, out int r);.

Rastreio: valor × ref × array 
static void A(int x)     { x = x + 10; }
static void B(ref int x) { x = x + 10; }
static void C(int[] v)   { v[0] = 99; v = new int[] { 0 }; }

int n = 1;  A(n);      // n continua 1
B(ref n);              // n = 11
int[] arr = { 5 };
C(arr);                // arr[0] = 99 (o conteúdo mudou; a troca de referência não volta)

12. Tratamento de exceções

Exceções representam erros em tempo de execução. Quando uma é lançada e não é tratada no método atual, ela sobe pela pilha de chamadas até encontrar um catch compatível; se não encontrar nenhum, o programa termina.

try
{
    int z = int.Parse(texto);               // código que pode falhar
    Console.WriteLine(100 / z);
}
catch (FormatException e)                   // do mais específico...
{
    Console.WriteLine("Formato inválido: " + e.Message);
}
catch (DivideByZeroException)               // a variável é opcional
{
    Console.WriteLine("Divisão por zero");
}
catch (Exception e) when (e is not OutOfMemoryException)   // ...ao mais geral; "when" é um filtro
{
    throw;                                  // relança preservando o stack trace original
}
finally
{
    Console.WriteLine("Sempre executa");    // com ou sem exceção, mesmo após return
}
  • Combinações válidas: try + um ou mais catch; try + finally; try + catch + finally. Um try sozinho não compila.
  • Um catch sem parênteses (catch { }) também é válido e captura qualquer exceção.
  • Os catch são testados em ordem. Colocar catch (Exception) antes de um mais específico gera erro de compilação, porque o específico nunca seria alcançado.
  • throw; relança mantendo o rastreamento original; throw e; relança mas reinicia o stack trace a partir daquele ponto. Para lançar uma nova: throw new ArgumentException("valor inválido");.
  • O finally executa mesmo que o try ou o catch tenham um return. Ele é o lugar de liberar recursos (fechar arquivos e conexões).
  • A instrução using (var r = ...) { } é uma forma resumida de try/finally que chama Dispose() no fim, para objetos que implementam IDisposable.

13. Diretivas de pré-processador

Linhas que começam com # são processadas pelo compilador antes da compilação propriamente dita. Elas não são instruções do programa, não terminam com ; e cada uma ocupa sua própria linha.

DiretivaFunção
#if, #elif, #else, #endifcompilação condicional: inclui ou exclui trechos conforme símbolos definidos
#define, #undefdefinem ou removem símbolos; precisam vir antes de qualquer outro código do arquivo
#region, #endregionmarcam blocos recolhíveis no editor; sem efeito no programa
#warning, #errorgeram um aviso ou um erro de compilação com a mensagem informada
#pragma warning disable, #nullable enable, #linecontrole de avisos, de análise de null e de numeração de linhas

Na configuração Debug de um projeto, o símbolo DEBUG já vem definido (e TRACE também); na configuração Release, DEBUG não é definido. Por isso a forma de ter comportamentos diferentes nos dois modos é:

#if DEBUG
    string logo = "logo-teste.png";
#else
    string logo = "logo.png";
#endif

Só um dos ramos entra no programa compilado. Os símbolos aceitam operadores lógicos: #if DEBUG && !TESTE. Uma alternativa para métodos inteiros é o atributo [Conditional("DEBUG")], que remove as chamadas ao método quando o símbolo não está definido. Já #ifdef e #ifndef são do C/C++ e não existem em C#.

15. Outras linguagens e tecnologias cobradas no mesmo bloco

Em provas de TI, o assunto "linguagens de programação" costuma misturar C# com conceitos gerais e com outras linguagens. Os pontos abaixo resolvem a maior parte dessas questões.

15.1 Compilação, interpretação e modelos híbridos

  • Compilador: traduz o programa inteiro para outra linguagem (normalmente código de máquina) antes da execução; os erros de sintaxe aparecem todos na compilação. Exemplos típicos: C, C++, Go, Rust, Pascal.
  • Interpretador: lê e executa o código-fonte instrução por instrução, sem gerar um executável separado; um erro numa linha só aparece quando ela é executada. São consideradas primordialmente interpretadas as linguagens de script: Perl, PHP, Python, Ruby e JavaScript (mesmo que, internamente, as implementações modernas gerem bytecode ou usem JIT).
  • Híbridas: compilam para um código intermediário executado por uma máquina virtual: Java (bytecode, JVM) e C# (IL, CLR).

15.2 JavaScript

JavaScript é uma linguagem interpretada, de tipagem dinâmica e fraca, executada no navegador (e no servidor, com Node.js). Para incluir um arquivo externo numa página usa-se <script src="js/app.js"></script>; o atributo type="text/javascript" é opcional no HTML5. Os pontos mais cobrados:

  • Declaração e escopo. var tem escopo de função e sofre hoisting (a declaração é "içada" para o topo da função, com valor undefined até a atribuição). let e const têm escopo de bloco. Atribuir a um nome nunca declarado, fora do modo estrito ("use strict"), cria uma variável global implícita.
  • undefined × null. undefined é o valor de uma variável declarada e não inicializada (ou de uma função sem return); null é atribuído de propósito. Usar um nome nunca declarado gera ReferenceError.
  • Igualdade. == converte os tipos antes de comparar ("1" == 1 é true); === compara valor e tipo ("1" === 1 é false).
  • Texto × número. O + com uma string concatena: "2" + 1 = "21". Os demais operadores aritméticos convertem para número: "6" * 2 = 12, "6" - 1 = 5. Valores lidos da página (innerHTML, value de um campo) são sempre strings; para somar, converte-se com Number(), parseInt() ou parseFloat().
  • DOM e eventos. document.getElementById("id") obtém um elemento; .innerHTML lê ou troca seu conteúdo; onclick="f()" chama a função a cada clique.
Rastreio: contador em um botão 
<p id="out">0</p>
<button onclick="soma()">+</button>
<script>
function soma() {
  var el = document.getElementById("out");
  el.innerHTML = Number(el.innerHTML) + 2;
}
</script>
Após 3 cliques o parágrafo mostra 6 (0 → 2 → 4 → 6). Sem o Number(), cada clique concatenaria texto: "02", "022", "0222".
Rastreio: global implícita e ordem de avaliação 
function g1() { k = 5; return k * 2; }   // sem var/let: k vira global
function g2() { return k * 3; }
console.log(g1() + g2());   // 10 + 15 = 25
Os operandos de + são avaliados da esquerda para a direita: g1() roda primeiro e cria k, então g2() já o encontra. Com g2() + g1(), a primeira chamada lançaria ReferenceError, pois k ainda não existiria.

15.3 Java

  • Arrays: int[] a = new int[5]; (zerado) ou int[] b = {1, 2, 3};. O tamanho é o atributo a.length (sem parênteses; em String é o método length()). Índice inválido lança ArrayIndexOutOfBoundsException.
  • Matrizes são arrays de arrays: int[][] m = {{1, 2}, {3, 4, 5}};. m.length é o número de linhas (2) e m[i].length o tamanho da linha i (as linhas podem ter tamanhos diferentes). m[1][2] vale 5. Para o primeiro elemento de cada linha: for (int i = 0; i < m.length; i++) System.out.println(m[i][0]); imprime 1 e 3.
  • Construtores: têm o mesmo nome da classe e nenhum tipo de retorno (nem void); podem ser sobrecarregados; podem ter qualquer modificador de acesso (public, protected, private ou o padrão). Se a classe não declara nenhum, o compilador cria um construtor padrão sem parâmetros; se declara algum, esse padrão deixa de existir. A chamada super(...) ou this(...), quando presente, tem que ser a primeira instrução. Classes abstratas podem ter construtores (chamados pelas subclasses); interfaces não têm. Construtores não são herdados.
  • Expressões regulares (java.util.regex): Pattern representa a expressão compilada (Pattern.compile("\\d+")); Matcher aplica o padrão a um texto (matches(), find(), group()); PatternSyntaxException sinaliza erro de sintaxe na expressão.

15.4 HTML5 e CSS3

  • <canvas> define uma área retangular de desenho em bitmap; os gráficos são desenhados por JavaScript (canvas.getContext("2d")). Sem script, o canvas fica vazio. Para gráficos vetoriais declarativos, o HTML5 aceita <svg>.
  • Outros elementos do HTML5: <video>, <audio> e os semânticos <header>, <nav>, <section>, <article>, <aside>, <footer>.
  • Formatação de texto: <b> negrito, <i> itálico, <u> sublinhado, <s> riscado, <strong> e <em> (ênfase com valor semântico), <mark> (destaque), <sub>/<sup>.

15.5 Web services e WSDL

A WSDL (Web Services Description Language) é um documento XML que descreve um web service: quais operações ele oferece, quais mensagens troca, em que protocolo e em que endereço. Normalmente é usada com SOAP. As duas versões têm nomes de elementos diferentes, e é aí que mora a cobrança:
