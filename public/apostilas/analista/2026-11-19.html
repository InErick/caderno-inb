Declaração, var, const e conversões

int idade = 30;
var nome = "Ana";        // var: o compilador deduz o tipo (string); segue tipado
const double PI = 3.14;  // constante: valor fixo em tempo de compilação
int x = (int)3.9;        // cast explícito: TRUNCA → 3 (não arredonda)
double d = idade;        // conversão implícita (int → double, sem perda)

double r2 = 7 / 2.0;     // um operando double → 3.5
Pegadinhasvar exige inicialização na mesma linha (var a; não compila) e só existe para variáveis locais. Variável local precisa receber valor antes de ser lida, senão é erro de compilação (não de execução). E Console.WriteLine de um bool imprime True/False, com inicial maiúscula.

2. Tipos anuláveis (int?) e o operador ??

Um tipo de valor como int não aceita null. Para permitir "sem valor", usa-se o tipo anulável: int? (abreviação de Nullable<int>). Ele tem as propriedades HasValue e Value.

O operador de coalescência nula ??

a ?? b significa: "use a; se a for null, use b". Não há nenhuma conta: é só uma escolha.

int? a = null;
int? b = 7;
double? c = 2.5;
Console.WriteLine(a ?? b);   // 7   (a é null → pega b)
Console.WriteLine(b ?? a);   // 7   (b não é null → fica com b)
Console.WriteLine(c ?? b);   // 2.5
Console.WriteLine(a ?? 0);   // 0   (valor padrão para "sem valor")
string s = null;
Console.WriteLine(s ?? "vazio");  // vazio

Se os dois lados forem null, o resultado é null, e o WriteLine imprime uma string vazia (nada aparece entre as vírgulas). Parentes do ??: x ??= y (atribui y só se x for null) e obj?.Prop (acessa a propriedade só se obj não for null; senão o resultado é null).

Comparações com null: a regra que a FGV adora

Quando um dos lados de uma comparação é um anulável null:

OperadorCom null de um ladonull com null
< > <= >=false, semprefalse
==falsetrue
!=truefalse
Exemplo resolvido 
int? p = null;  int q = 10;  int? z = null;
Console.WriteLine(p > q);    // False  (null não é maior nem menor)
Console.WriteLine(p <= q);   // False  (nem "menor ou igual"!)
Console.WriteLine(q != p);   // True   (10 é diferente de "sem valor")
Console.WriteLine(z == p);   // True   (null == null)
O detalhe que derruba muita gente: p <= q é False e p > q também é False. Com null, as duas comparações de ordem são falsas ao mesmo tempo.

3. Operadores

Aritméticos e o resto (%)

+ - * / %. O % devolve o resto da divisão inteira: 32 % 3 = 2 (pois 3 × 10 = 30, sobra 2). Com negativos, o resultado tem o sinal do dividendo (o da esquerda): -7 % 3 = -1 e 7 % -3 = 1. Truque útil: i % 2 == 0 testa se i é par.

Incremento: pré × pós

int a = 5;
int b = ++a;   // pré: incrementa primeiro, depois usa → a = 6, b = 6
int c = a++;   // pós: usa primeiro, depois incrementa → c = 6, a = 7
int d = ++a + 1;  // a vira 8, d = 9

Deslocamento de bits (>> e <<)

Deslocar n bits para a direita equivale a dividir por 2ⁿ (descartando a parte fracionária); para a esquerda, a multiplicar por 2ⁿ. Vale para positivos; com negativos, o >> arredonda para baixo (-9 >> 1 = -5).

20 >> 2   // 20 / 4 = 5       (10100 → 00101)
9 >> 1    // 9 / 2 = 4        (1001 → 0100)
3 << 3    // 3 × 8 = 24
Rastreio completo (estilo FGV) 
int[] v = { 12, 20, 17 };
v[0] = v[0] >> 1;      // 12 / 2 = 6
v[1] = v[1]++ + 2;     // usa 20, soma 2 → 22 (o ++ "se perde": a atribuição sobrescreve)
v[2] = v[2] % 5;       // 17 = 5×3 + 2 → 2
foreach (int n in v) Console.WriteLine(n);   // 6, 22, 2
Repare no v[1]++: é pós-incremento, então a expressão vale 20; o resultado 22 é gravado em v[1] por cima do incremento. Se fosse ++v[1] + 2, daria 21 + 2 = 23.

4. Decisões: if e switch

if (nota >= 7) Console.WriteLine("Aprovado");
else if (nota >= 5) Console.WriteLine("Recuperação");
else Console.WriteLine("Reprovado");

switch (dia)
{
    case 1:
    case 7:                       // rótulos vazios podem ser empilhados
        Console.WriteLine("Fim de semana");
        break;                    // obrigatório: C# não deixa "cair" para o próximo case
    case 2:
        Console.WriteLine("Segunda");
        break;
    default:
        Console.WriteLine("Dia útil");
        break;
}
Diferenças em relação a C/JavaA condição do if tem que ser bool: if (x = 5) ou if (1) não compilam. No switch, uma seção com código que não termina em break, return, throw ou goto case é erro de compilação (não existe fall-through implícito). E o switch aceita string.

5. Laços, break, continue e escopo

for (int i = 0; i < 3; i++) { ... }     // inicialização; condição; passo
while (cond) { ... }                     // testa antes (pode rodar 0 vezes)
do { ... } while (cond);                 // testa depois (roda pelo menos 1 vez)
foreach (var item in lista) { ... }      // percorre coleção (item é somente leitura)
for (;;) { ... }                         // laço infinito válido (sai com break/return)

break × continue

  • break: sai do laço imediatamente.
  • continue: pula o resto desta volta e vai para a próxima.
Contando chamadas 
for (int i = 1; i <= 6; i++) {
    if (i % 3 == 0) break;
    A(i);                 // i = 1, 2 → A chamada 2 vezes; em i = 3 o laço acaba
}
for (int i = 1; i <= 6; i++) {
    if (i % 3 == 0) continue;
    B(i);                 // pula 3 e 6 → B chamada 4 vezes (1, 2, 4, 5)
}
Atenção ao valor inicial: se o laço começar em i = 0 e o teste for i % 2 == 0 com break, o laço termina na primeira volta (0 é par), e a função nunca é chamada.

Escopo da variável do for

A variável declarada no cabeçalho do for só existe dentro do laço. Usá-la depois gera erro de compilação ("o nome 'i' não existe no contexto atual"), não erro de execução:

for (int i = 0; i < 5; i++) { }
Console.WriteLine(i);      // ❌ não compila

int j;
for (j = 0; j < 5; j++) { }
Console.WriteLine(j);      // ✅ imprime 5 (j foi declarada fora)

Também vale saber: sobrecarga (overload) é ter vários métodos com o mesmo nome e listas de parâmetros diferentes; o tipo de retorno sozinho não diferencia sobrecargas. Parâmetros opcionais vêm depois dos obrigatórios, e params tem que ser o último.

7. Exceções, diretivas de pré-processador e arquivos

Estrutura de tratamento de erros

try
{
    int z = int.Parse(texto);          // código que pode falhar
}
catch (FormatException e)              // mais específica primeiro
{
    Console.WriteLine(e.Message);
}
catch (Exception e)                    // mais geral por último
{
    throw;                             // relança mantendo o stack trace
}
finally
{
    Console.WriteLine("sempre executa");  // com ou sem exceção
}
O que a banca trocaAs alternativas erradas inventam on error, except (Python) ou rescue (Ruby). Em C#: try / catch (Tipo nome) / finally; um catch { } sem parênteses também é válido (captura qualquer exceção), e try + finally sem catch também. Um catch genérico antes de um específico não compila. O tema volta com mais profundidade no dia de Exceções + SOLID.

Debug × Release: #if DEBUG

As diretivas de pré-processador começam com # e são avaliadas na compilação. Na configuração Debug, o símbolo DEBUG já vem definido; na Release, não. Assim, só um dos blocos entra no programa compilado:

#if DEBUG
    imagem = "logo-teste.png";
#else
    imagem = "logo.png";
#endif

Outras diretivas: #define/#undef (definem símbolos, no topo do arquivo), #elif, #region/#endregion (só organização visual), #warning e #error. Note que é #if … #endif, sem chaves e sem parênteses obrigatórios.

Arquivos: a classe estática System.IO.File

A FGV cobra a lista de métodos válidos. Os principais (todos estáticos):

FileStream e o enum FileMode

using (var fs = new FileStream("dados.txt", FileMode.OpenOrCreate, FileAccess.ReadWrite)) { ... }
FileModeComportamento
CreateNewcria; dá erro se o arquivo já existir
Createcria; se existir, sobrescreve

São seis. Nomes como Rewrite, Overwrite ou ReadWrite não são FileMode (ReadWrite é valor de FileAccess, outro enum). O using garante que o arquivo seja fechado no fim do bloco.

Para memorizar os 6 FileModePense no ciclo de vida: Create, CreateNew (nascer), Open, OpenOrCreate (abrir), Truncate (esvaziar), Append (acrescentar).

JavaScript: texto × número e ordem de avaliação

O + com uma string concatena; os outros operadores aritméticos convertem para número. Valores lidos da página (innerHTML, value de um campo) são strings.

"2" + 1        // "21"  (concatena)
"2" * 3        // 6     (converte para número)
Number("2") + 1   // 3
parseInt("7px")   // 7
Rastreio: botão e variável global 
<p id="out">0</p>
<button onclick="soma()">+</button>
<script>
function soma() {
  var el = document.getElementById("out");
  el.innerHTML = Number(el.innerHTML) + 2;   // 2, 4, 6 ...
}
</script>
Clicando 3 vezes, o parágrafo mostra 6. Sem o Number(), o resultado seria texto: "02", depois "022", "0222".
function g1() { k = 5; return k * 2; }   // k vira global
function g2() { return k * 3; }
console.log(g1() + g2());                 // 10 + 15 = 25
A expressão é avaliada da esquerda para a direita: g1() roda primeiro e cria a global k = 5, então g2() já a enxerga. Se a ordem fosse g2() + g1(), daria erro (k ainda não existe).

Java

  • Arrays: int[] a = new int[5]; ou int[] b = {1, 2, 3};. Índices de 0 a length - 1; a.length é atributo (sem parênteses). Acessar fora gera ArrayIndexOutOfBoundsException.
  • Matrizes (arrays de arrays): int[][] m = {{1, 2}, {3, 4, 5}};. m.length é o número de linhas (2) e m[i].length o tamanho da linha i (as linhas podem ter tamanhos diferentes). m[1][2] vale 5. Para pegar o primeiro elemento de cada linha: for (int i = 0; i < m.length; i++) System.out.println(m[i][0]); → 1 e 3.
  • Construtores: mesmo nome da classe, sem tipo de retorno, podem ser sobrecarregados; o construtor padrão só é criado se a classe não declarar nenhum. Classe abstrata pode ter construtor; interface não tem. O construtor aceita qualquer modificador de acesso (public, protected, private ou o padrão); não precisa ser private.
  • Expressões regulares (java.util.regex): as três classes são Pattern (a expressão compilada), Matcher (aplica a expressão a um texto: matches(), find(), group()) e PatternSyntaxException (erro de sintaxe na expressão).

Exercícios de fixação (inéditos)

Questão 1 · inédita

Considere o trecho em C#:

int[] t = { 7, 48, 25 };
t[0] = t[0] % 4;
t[1] = t[1] >> 3;
t[2] = t[2]++ - 5;
foreach (int k in t) Console.Write(k + " ");

A saída é:

  1. 3 6 20
  2. 3 6 21
  3. 1 6 20
  4. 3 16 21
  5. 3 5 20
Ver gabarito comentado

Gabarito: A. 7 % 4 = 3 (7 = 4 + 3). 48 >> 3 = 48 ÷ 8 = 6. t[2]++ vale 25 na expressão (pós-incremento), 25 − 5 = 20, e a atribuição grava 20 por cima. A alternativa B é a pegadinha de quem trata o pós como pré.

Questão 2 · inédita

Em C#, assinale a opção que contém apenas operadores de comparação válidos.

  1. == <> >=
  2. === != <
  3. != <= >
  4. = == !=
  5. =< => ==
Ver gabarito comentado

Gabarito: C. <> é de VB/SQL, === é de JavaScript, = é atribuição e =< não existe (=> é o operador lambda, não comparação).

Questão 3 · inédita

Analise:

int? m = null;  int? n = 3;  int? o = null;
Console.WriteLine(m ?? n);
Console.WriteLine(m < n);
Console.WriteLine(o == m);
Console.WriteLine(n != m);

São exibidos, na ordem:

  1. 3, True, True, True
  2. 3, False, True, True
  3. (vazio), False, False, True
  4. 3, False, False, False
  5. null, False, True, True
Ver gabarito comentado

Gabarito: B. m ?? n: m é null, então 3. m < n: comparação de ordem com null é sempre False. o == m: null == null é True. n != m: 3 é diferente de null, True.

Questão 4 · inédita

Considere:

for (int i = 1; i <= 10; i++) {
    if (i % 4 == 0) continue;
    P(i);
}
for (int i = 1; i <= 10; i++) {
    if (i % 4 == 0) break;
    Q(i);
}

Os métodos P e Q são chamados, respectivamente:

  1. 8 e 3 vezes
  2. 7 e 3 vezes
  3. 8 e 4 vezes
  4. 10 e 3 vezes
  5. 2 e 8 vezes
Ver gabarito comentado

Gabarito: A. No primeiro laço, o continue pula os múltiplos de 4 entre 1 e 10 (4 e 8): 10 − 2 = 8 chamadas. No segundo, o break encerra o laço em i = 4, então Q roda para 1, 2 e 3.

Questão 5 · inédita

Sobre o código abaixo, é correto afirmar que:

static void Main() {
    int total = 0;
    for (int k = 0; k < 3; k++) total += k;
    Console.WriteLine(total + k);
}
  1. exibe 6
  2. exibe 3
  3. exibe 5
  4. gera erro de compilação
  5. gera uma exceção em tempo de execução
Ver gabarito comentado

Gabarito: D. k foi declarada no cabeçalho do for e não existe fora dele. O compilador recusa o programa antes de qualquer execução.

Questão 6 · inédita

Um programa deve gravar logs detalhados apenas quando compilado na configuração Debug. A construção adequada em C# é:

  1. if (DEBUG) { Log(); }
  2. #if DEBUG Log(); #endif, com cada diretiva em sua própria linha
  3. #ifdef DEBUG { Log(); }
  4. #when DEBUG Log(); #end
  5. @if(Debug) Log(); @endif
Ver gabarito comentado

Gabarito: B. Em C# a compilação condicional usa #if / #else / #endif, cada diretiva em uma linha. #ifdef é de C/C++; if (DEBUG) trataria DEBUG como variável, que não existe.
