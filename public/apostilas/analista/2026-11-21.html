Orientação a Objetos I: classes, objetos, encapsulamento, herança e uma primeira visão de polimorfismo

A orientação a objetos é o paradigma em que o C# (e Java, C++, Python…) foi construído, e é um dos temas mais cobrados em provas de Analista de Sistemas. Este capítulo apresenta os conceitos fundamentais (classe, objeto, atributo, método, construtor), os quatro pilares (abstração, encapsulamento, herança e polimorfismo) com a sintaxe do C#, as diferenças entre sobrecarga e sobrescrita, as noções de coesão e acoplamento, a programação orientada a eventos e uma introdução à refatoração. O próximo capítulo de POO aprofunda classes abstratas, interfaces e composição.

Específicos · Orientação a Objetos⏱ 1 hora
Como estudar este capítuloPara cada conceito, pense em um exemplo do mundo real (uma conta bancária, um funcionário, um veículo) e escreva no papel a classe correspondente. Desenhar a hierarquia de classes e dizer, em voz alta, "um Gerente é um Funcionário" ajuda a fixar herança; prever qual método será executado em cada chamada ajuda a fixar polimorfismo.

1. Paradigmas de programação

Um paradigma é um modo de organizar e pensar um programa. Os mais cobrados:

ParadigmaIdeia centralExemplos
Estruturado / proceduralo programa é uma sequência de procedimentos (funções) que operam sobre dados separados deles; usa sequência, decisão e repetiçãoC, Pascal
Orientado a objetoso programa é um conjunto de objetos que reúnem dados (estado) e comportamento (métodos) e colaboram trocando mensagensC#, Java, C++, Python, Smalltalk
Funcionalcomputação como avaliação de funções matemáticas, sem estado mutável nem efeitos colateraisHaskell, F#, Lisp
Lógicoo programa declara fatos e regras, e um mecanismo de inferência responde consultasProlog
Orientado a eventoso fluxo do programa é determinado por eventos (cliques, teclas, mensagens), tratados por funções chamadas handlersinterfaces gráficas, JavaScript no navegador, ASP.NET Web Forms

As vantagens atribuídas à orientação a objetos são reutilização de código (por herança e composição), modularidade, facilidade de manutenção e extensibilidade, além de uma maior proximidade entre o modelo do software e os conceitos do problema real.

2. Classes, objetos, atributos e métodos

ConceitoDefiniçãoAnalogia
Classemodelo (molde) que define os atributos e os métodos que os objetos daquele tipo terão; é um tipo definido pelo programadora planta de uma casa
Objeto (instância)entidade concreta criada a partir de uma classe, ocupando memória em tempo de execução, com seu próprio estadocada casa construída com a planta

Todo objeto tem estado (valores dos atributos), comportamento (métodos) e identidade (é distinguível de outro objeto, mesmo com estado igual).

public class ContaBancaria
{
    // atributos (campos)
    private string titular;
    private decimal saldo;

    // construtor: inicializa o objeto
    public ContaBancaria(string titular, decimal saldoInicial)
    {
        this.titular = titular;      // this: o próprio objeto
        this.saldo = saldoInicial;
    }

    // métodos: comportamento
    public void Depositar(decimal valor)
    {
        if (valor <= 0) throw new ArgumentException("Valor inválido");
        saldo += valor;
    }

    public decimal ConsultarSaldo() => saldo;
}

// uso: criando (instanciando) objetos com new
var c1 = new ContaBancaria("Ana", 100m);
var c2 = new ContaBancaria("Bia", 0m);
c1.Depositar(50m);          // c1 tem saldo 150; c2 continua 0

Uma variável de tipo classe guarda uma referência ao objeto. Fazer var c3 = c1; não cria um objeto novo: c3 e c1 passam a apontar para a mesma conta.

Construtores

  • Têm o mesmo nome da classe e não têm tipo de retorno (nem void). São executados automaticamente na criação do objeto (new).
  • Se a classe não declara nenhum construtor, o compilador fornece um construtor padrão sem parâmetros. Se a classe declara algum, esse padrão deixa de existir.
  • Podem ser sobrecarregados e um pode chamar outro da mesma classe com : this(...), ou um construtor da classe base com : base(...).
  • Construtores não são herdados. Classes abstratas podem ter construtores (chamados pelas subclasses); interfaces não têm.
  • Um construtor private impede a criação de objetos de fora da classe (usado no padrão Singleton e em classes utilitárias).
  • O C# também tem finalizadores (~ContaBancaria()), chamados pelo coletor de lixo; para liberar recursos de forma determinística, usa-se IDisposable e using.

Membros de instância × membros estáticos

Atributos e métodos comuns pertencem a cada objeto. Membros static pertencem à classe e são compartilhados por todos os objetos. Um contador de quantas contas foram criadas seria private static int total;. Métodos estáticos são chamados pelo nome da classe (Math.Sqrt(9)) e não podem acessar membros de instância diretamente (não existe this em contexto estático). Uma static class não pode ser instanciada nem herdada.

3. Os quatro pilares

A literatura apresenta a orientação a objetos sobre quatro pilares (algumas obras listam só três, sem a abstração, ou acrescentam outros):

4. Abstração

Abstrair é selecionar o que importa. Uma classe Paciente num sistema hospitalar terá nome, CPF, alergias e histórico; num sistema de estacionamento, a mesma pessoa seria só um Cliente com placa e horário de entrada. A abstração define a interface de uma classe (o que o objeto é e o que ele faz), deixando de fora como ele faz. É, nas palavras usuais das provas, a supressão intencional (ou ocultação) de detalhes para se concentrar nos aspectos essenciais.

Na prática da linguagem, a abstração aparece também em classes abstratas e métodos abstratos: uma classe que representa um conceito genérico demais para ter objetos próprios.

public abstract class Funcionario
{
    public string Nome { get; set; }
    public abstract decimal CalcularRemuneracao();   // sem corpo: cada subclasse implementa
}
// new Funcionario()  → ❌ erro de compilação: classe abstrata não pode ser instanciada

Uma classe abstrata não pode ser instanciada; pode ter métodos concretos e abstratos, atributos e construtores. Toda classe concreta que herda dela deve implementar (sobrescrever) todos os métodos abstratos. Esse tema é aprofundado no capítulo de POO II.

5. Encapsulamento

Encapsular é proteger os dados internos de um objeto, controlando o acesso a eles. Os atributos ficam privados e o acesso é feito por métodos (ou, em C#, propriedades) públicos, que podem validar as alterações. Assim, o objeto garante que seu estado esteja sempre consistente, e a implementação interna pode mudar sem afetar quem usa a classe (ocultação de informação, information hiding).

Por que encapsularSe saldo fosse público, qualquer parte do sistema poderia fazer conta.saldo = -1000000;. Com o atributo privado, a única forma de alterar o saldo é pelos métodos Depositar e Sacar, que verificam as regras de negócio. Em um sistema que grava objetos em uma tabela do banco de dados, o padrão é o mesmo: atributos privados e métodos ou propriedades públicos de leitura e gravação.

Modificadores de acesso do C#

Em Java, os níveis são public, protected (pacote + subclasses), o padrão sem palavra-chave (package-private) e private. Na UML, a visibilidade é indicada por símbolos: + público, - privado, # protegido, ~ pacote.

Propriedades

Em C#, o jeito idiomático de encapsular é a propriedade, que parece um atributo para quem usa, mas executa métodos get e set:

public class Produto
{
    private decimal preco;                 // campo de apoio (backing field)
    public decimal Preco
    {
        get { return preco; }
        set
        {
            if (value < 0) throw new ArgumentException("Preço negativo");
            preco = value;                 // value: valor atribuído
        }
    }
    public string Nome { get; set; }       // propriedade automática
    public int Codigo { get; private set; } // leitura pública, escrita só dentro da classe
    public DateTime Criacao { get; } = DateTime.Now; // somente leitura (init no construtor ou inicializador)
}
var p = new Produto { Nome = "Caneta", Preco = 2.5m };   // inicializador de objeto
p.Preco = -1;   // lança ArgumentException: a regra está protegida

Em Java, o equivalente são os métodos getters e setters (getPreco(), setPreco(...)).

6. Herança

Herança é o mecanismo pelo qual uma classe (subclasse, classe derivada, classe filha) é definida a partir de outra (superclasse, classe base, classe pai), herdando seus atributos e métodos e podendo acrescentar novos membros e especializar (sobrescrever) comportamentos. Representa a relação "é um" (is-a): um Gerente é um Funcionário. Dizer que "a classe A estende a classe B" é o mesmo que dizer que A é derivada de B (A é a subclasse).

public class Pessoa
{
    public string Nome { get; set; }
    public string Cpf { get; set; }
    public Pessoa(string nome) { Nome = nome; }
    public virtual string Apresentar() => $"Sou {Nome}";
}

public class Funcionario : Pessoa                 // ":" indica herança em C# (extends em Java)
{
    public decimal Salario { get; set; }
    public Funcionario(string nome, decimal salario) : base(nome)   // chama o construtor da base
    {
        Salario = salario;
    }
    public override string Apresentar() => base.Apresentar() + $", ganho {Salario:C}";
}
  • Em C# (e em Java), uma classe herda de uma única classe (herança simples), mas pode implementar várias interfaces. O C++ admite herança múltipla de classes.
  • Toda classe C# deriva, direta ou indiretamente, de System.Object (object). Escrever class X : Object é válido, mas redundante. Por isso todo objeto tem ToString(), Equals(), GetHashCode() e GetType(). Em Java, a raiz é java.lang.Object.
  • base (C#) ou super (Java) acessa membros e construtores da classe base. O construtor da base é sempre executado antes do construtor da derivada.
  • Membros private da base existem no objeto derivado, mas não são acessíveis diretamente pela subclasse; os protected são.
  • sealed (C#) ou final (Java) numa classe impede que ela seja herdada (ex.: string é sealed). Num método override, sealed impede novas sobrescritas.

Conversões entre tipos da hierarquia

Pessoa p = new Funcionario("Ana", 5000m);   // upcasting: implícito e sempre seguro
Funcionario f = (Funcionario)p;            // downcasting: explícito; falha com InvalidCastException se p não for Funcionario
if (p is Funcionario fx) { /* usa fx */ }  // teste seguro com is
Funcionario? g = p as Funcionario;         // as: devolve null se não for possível

Generalização, especialização e cuidados

Chama-se generalização o processo de extrair o que é comum a várias classes para uma superclasse, e especialização o caminho inverso. Herança aumenta o reaproveitamento, mas também o acoplamento: mudanças na superclasse afetam todas as subclasses (problema da "classe base frágil"). Por isso a recomendação clássica "prefira composição a herança" (aprofundada no capítulo de POO II): use herança apenas quando a relação "é um" for verdadeira e estável.

7. Polimorfismo: sobrescrita e sobrecarga

Polimorfismo (muitas formas) é a capacidade de uma mesma chamada produzir comportamentos diferentes conforme o objeto que a recebe. Ele permite que objetos de classes diferentes sejam tratados de maneira uniforme por meio de uma interface comum (uma superclasse ou uma interface), sem que o código cliente precise saber o tipo exato de cada um.

Sobrescrita (override) e ligação dinâmica

Na sobrescrita, uma subclasse redefine um método herdado com a mesma assinatura, especializando o comportamento. Em C#, o método da base precisa ser marcado como virtual (ou abstract), e o da derivada como override. A decisão de qual versão executar é feita em tempo de execução, pelo tipo real do objeto (ligação tardia ou dinâmica, late binding).

public abstract class Funcionario
{
    public decimal SalarioBase { get; set; }
    public abstract decimal CalcularSalario();
}
public class Gerente : Funcionario
{
    public override decimal CalcularSalario() => SalarioBase * 1.3m;   // bônus de gestão
}
public class Vendedor : Funcionario
{
    public decimal Vendas { get; set; }
    public override decimal CalcularSalario() => SalarioBase + Vendas * 0.05m;  // comissão
}

List<Funcionario> folha = new() { new Gerente { SalarioBase = 10000 },
                                  new Vendedor { SalarioBase = 3000, Vendas = 20000 } };
foreach (Funcionario f in folha)
    Console.WriteLine(f.CalcularSalario());   // 13000 e 4000: cada objeto executa a sua versão

A referência é do tipo Funcionario, mas cada chamada executa a versão da classe real do objeto. Isso é o polimorfismo de inclusão (ou de subtipo). Em Java, todo método de instância não final já é "virtual" por padrão.

virtual/override × newSe a derivada declarar o método com new (ou sem override, o que gera aviso), ela apenas oculta (hiding) o método da base: a versão executada passa a depender do tipo da referência, e não do objeto. Pessoa p = new Funcionario(...); p.Metodo(); chamaria a versão de Pessoa. Sem virtual na base, não há polimorfismo de sobrescrita em C#.

Sobrecarga (overload)

Na sobrecarga, vários métodos na mesma classe (ou herdados) têm o mesmo nome e listas de parâmetros diferentes (quantidade, tipos ou ordem). O compilador escolhe a versão em tempo de compilação, pelos argumentos (ligação estática). O tipo de retorno sozinho não diferencia sobrecargas.

public class Calculadora
{
    public int Somar(int a, int b) => a + b;
    public int Somar(int a, int b, int c) => a + b + c;
    public double Somar(double a, double b) => a + b;
    // public double Somar(int a, int b) => ...   ❌ só o retorno é diferente: não compila
}

8. Coesão e acoplamento

  • Coesão mede o quanto as responsabilidades de uma classe estão relacionadas entre si. Busca-se alta coesão: cada classe com um conjunto limitado e bem definido de responsabilidades (uma classe Relatorio não deveria também enviar e-mails e acessar o banco).
  • Acoplamento mede o grau de dependência entre classes. Busca-se baixo acoplamento: classes que dependem pouco umas das outras, de preferência de abstrações (interfaces), e não de implementações concretas.

Alta coesão e baixo acoplamento facilitam manutenção, testes e reutilização. Esses conceitos fundamentam os princípios SOLID (estudados no capítulo de Exceções e SOLID). Um deles já aparece em problemas de design: o Princípio da Inversão de Dependência (DIP), segundo o qual módulos de alto nível não devem depender de módulos de baixo nível, e sim ambos de abstrações. Exemplo: uma classe de exportação que instancia diretamente ExportadorXml, ExportadorJson e ExportadorTexto com uma cadeia de if viola o DIP; o ideal é que ela dependa de uma interface IExportador, com as implementações injetadas.

9. Programação orientada a eventos

Na programação orientada a eventos, o programa fica aguardando acontecimentos (clique, digitação, carregamento da página, chegada de mensagem) e, quando um evento é disparado, executa o método associado a ele, chamado manipulador (event handler). O fluxo não é uma sequência fixa: depende da ordem em que os eventos acontecem.

No ASP.NET Web Forms, a página .aspx declara o controle e associa o evento ao método, que fica no arquivo de código (code-behind):

<asp:Button ID="btnEnviar" runat="server" Text="Enviar" OnClick="ButtonClick" />

// code-behind (.aspx.cs)
protected void ButtonClick(object sender, EventArgs e)
{
    lblMensagem.Text = "Formulário enviado!";
}

Aqui, OnClick (o atributo do evento Click) é o evento, e ButtonClick é o método que manipula o evento quando ele é disparado. A assinatura padrão de um handler no .NET recebe object sender (quem disparou) e um EventArgs (dados do evento). Em C#, eventos são baseados em delegates, e a inscrição é feita com +=: btnEnviar.Click += ButtonClick;.

10. Introdução à refatoração

Refatorar é alterar a estrutura interna do código sem mudar seu comportamento externo, para torná-lo mais legível e fácil de manter. Martin Fowler catalogou sintomas de código problemático (code smells) e as refatorações correspondentes:

Code smellSintomaRefatoração típica
Método longométodo enorme, difícil de entenderExtract Method (extrair método)
Classe grandeclasse com responsabilidades demais (baixa coesão)Extract Class
Código duplicadoa mesma lógica em vários lugaresExtract Method, Pull Up Method (subir para a superclasse)
Inveja de recursos (Feature Envy)um método usa mais os dados de outra classe que os da suaMove Method
Cadeia de mensagensa.GetB().GetC().GetD(): o cliente depende da navegação entre objetosHide Delegate (criar na classe intermediária um método que esconde a cadeia)
Intermediário (Middle Man)uma classe passa a ter muitos métodos que apenas delegam para outra, sem lógica própria; isso costuma surgir quando Hide Delegate é aplicado em excessoRemove Middle Man (o cliente passa a chamar o objeto delegado diretamente)
Lista longa de parâmetrosmétodos com muitos argumentosIntroduce Parameter Object
Switch repetido por tipocondicionais sobre o tipo do objeto espalhadas pelo códigoReplace Conditional with Polymorphism
Hide Delegate × Remove Middle ManUm gráfico precisa da população de um estado e faz municipio.GetEstado().GetPopulacao(). Para esconder a navegação, cria-se municipio.GetPopulacaoEstado(), que apenas delega (Hide Delegate). Se, com o tempo, a classe Municipio ganha dezenas desses métodos que só repassam chamadas, ela vira um intermediário sem valor próprio, e a refatoração indicada é Remove Middle Man: os clientes voltam a acessar o objeto delegado diretamente.

Exercício 4

Considere o código C#:

class A { public virtual string F() => "A"; }
class B : A { public override string F() => "B"; }
class C : A { public new string F() => "C"; }

A x = new B();  A y = new C();  C z = new C();
Console.WriteLine(x.F() + y.F() + z.F());

A saída é:

  1. BCC
  2. AAC
  3. BAC
  4. BAA
  5. ABC
Ver gabarito comentado

Gabarito: C. x referencia um B, que sobrescreve F: "B". y é referência do tipo A para um C que apenas oculta F com new: vale a versão de A, "A". z é referência do tipo C: "C".

Exercício 7

Sobre herança em C#, assinale a afirmativa correta.

  1. Uma classe pode herdar de várias classes, separadas por vírgula.
  2. Os construtores da classe base são herdados pela classe derivada.
  3. Uma classe marcada como sealed pode ser herdada apenas no mesmo assembly.
  4. Toda classe deriva, direta ou indiretamente, de System.Object.
  5. Membros private da base podem ser acessados diretamente pela derivada.
Ver gabarito comentado

Gabarito: D. C# tem herança simples de classes (A); construtores não são herdados (B); sealed impede qualquer herança (C); private não é acessível na derivada (E).

Exercício 8

Considere:

class Base {
    public Base() { Console.Write("1"); }
}
class Deriv : Base {
    public Deriv() : base() { Console.Write("2"); }
    public Deriv(int x) : this() { Console.Write("3"); }
}
new Deriv(5);

A saída é:

  1. 3
  2. 23
  3. 123
  4. 321
  5. 13
Ver gabarito comentado

Gabarito: C. Deriv(int) encadeia para Deriv(), que encadeia para Base(). Os corpos executam da base para a derivada: 1, depois 2, depois 3.
